All user's input intention should be journaled in a docs folder with a separate file for each PR.

## Documentation

- Keep `README.md` focused on players. Update it when changes affect how players start, control, or play the game.
- Document logic changes in `docs/technical.md`. Keep local setup, architecture, configuration, diagnostics, and testing instructions there.

## Comments in code
- All non-trivial logic must be explained in code comments at the top of a function or class.
- Comments should describe the intent, assumptions, or logic behind the code.
- Reviewer checks comments match updated logic.
